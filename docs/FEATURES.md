# BiliKit Performance 功能介绍

当前版本：**0.7.4**

BiliKit Performance 是面向 Edge / Chromium 的 Bilibili userscript，主要提供播放交互、播放器下载工作台、收藏夹失效视频修复和桌面端首页信息流增强。详细实现以当前发布脚本为准：[bilikit-performance.user.js](../bilikit-performance.user.js)。

## 首页、搜索和 CDN

- 首页保留 B 站原生卡片排布、展示位、推荐顺序和滚动加载，不接管横向列数、纵向行数，也不使用 CSS Grid 重排。
- 首页只做小范围优化：广告删除、封面预加载、图片节点优化、请求预连接和原生布局稳定性保护；脚本保留 B 站原生列数/行数，只在网格直接卡片上清除额外上边距，不写入卡片布局属性，相关资源优化可以在设置中独立关闭。
- 停止滚动后的自动加载只协调 B 站原生入口，不自行渲染接口结果、不克隆卡片、不伪造 scroll 事件，并在检测到 BiliKit Feed 时让路。
- 首页与搜索页封面预览直接由 Performance 提供，真视频模式使用 B 站播放接口获取静音低清地址并在悬停时播放，动态追加卡片自动接入；不依赖 BiliKit Feed。
- 首页诊断接口包括 `window.__BILIKIT_HOME_FEED_STATS__`、`window.__BILIKIT_HOME_FEED_COORDINATOR_STATS__`、`window.__BILIKIT_HOME_FEED_PRIORITY_STATS__`、`window.__BILIKIT_HOME_AUTO_LOAD_STATS__`、`window.__BILIKIT_HOME_LAYOUT_STATS__` 和 `window.__BILIKIT_HOME_AD_STATS__`。
- 搜索页只保留独立的连接和已知接口 URL 处理，搜索结果与悬停预览继续使用 B 站原生逻辑。
- CDN 优选当前只处理播放资源和悬停预览的精确 `playurl` 响应，不伪造 MCDN 签名。

## 播放交互

- 视频卡片支持抽屉、新标签页或当前页打开。
- 播放页提供“回程”能力，可返回上一个视频并按设置恢复播放进度。
- 正式播放时可申请 Screen Wake Lock，减少设备自动休眠；悬停预览不会申请唤醒锁。
- “稍后再看”“不感兴趣”和“更多”等原生操作继续交给 B 站处理。
- “未登录提示拦截”模块可在首页首次进入时开启，也可在设置中修改；开启后覆盖首页、视频页等页面的登录弹窗、登录浮层和登录提示卡，只处理 DOM，不改写评论或播放请求。
- 评论链接识别模块会把 Unicode Emoji、B 站表情图片和表情资源路径视为拆分分隔符，识别合法 HTTPS 链接并提供新标签页按钮。

## 播放器下载工作台

工作台可以从播放器右键菜单打开，也可以点击 Bilibili 顶栏“下载”入口后输入 BV 号直接打开；顶栏空间不足时会自动显示在右下角 BiliKit 齿轮上方。工作台使用 B 站官方播放信息，不调用第三方下载接口。下载显示项和刷新参数可在“下载工作台”模块中调整。

### 普通视频模式

普通视频模式使用一个统一的视频列表，同时处理同一 BV 的分 P 和不同 BV 的合集：

- 当前 BV 的分 P 使用 `P01`、`P02` 标识。
- 合集视频使用 `C01`、`C02` 作为父项；父项可以一次选择该 BV 的全部 P，子项使用 `C01_P01`、`C01_P02` 等标识。
- 合集视频与其内部 P、当前 BV 的普通分 P 可以同时加入同一批任务；推荐列表中无关的其他 BV 不会被加入。
- 默认只勾选当前视频，支持“全选”“取消全选”和逐项选择。每个实际任务都独立使用自己的 BVID/AV、CID 和播放接口响应。

支持三种操作：

1. 合并视频和音频为 MP4；
2. 分别下载视频轨和音频轨；
3. 仅下载音频轨。

清晰度和编码以当前选择为目标，其他视频按相同清晰度同编码、相同清晰度其他编码、较低清晰度、最低可用清晰度的顺序匹配。合并是 MP4 直通重封装，不重新编码；资源不可用、过期、付费或受保护时不会绕过限制。

### 番剧模式

番剧模式与普通视频模式独立，识别 B 站 `/bangumi/play/` 页面，并读取官方 PGC 季度和正片集目录：

- 单季度按 `E01`、`E02` 展示；多季度按 `S01E01`、`S02E01` 展示，并以季度父项支持整季选择。
- 默认只勾选当前集，也支持季度全选、列表全选、取消全选和单集选择。
- 每集独立使用自己的 `season_id`、`ep_id`、BVID/AID 和 CID 获取播放轨道，不混用普通视频模式的目录或缓存。
- 番剧远程目录和播放请求最多并发 2 个；轨道取得后，本地 MP4 合并仍使用独立的合并调度。

### 下载任务和合并调度

- 分轨任务在确认轨道后直接交给浏览器下载管理器，不进入本地合并任务池。
- 合并任务最多同时运行 4 个，并根据 CPU、可用内存、视频时长、码率和清晰度估算容量；超出预算或超长任务会排队。
- 单个任务失败、取消或重试不会阻断同批次其他任务；切换视频、分 P、合集或番剧页面时会清理旧任务和旧轨道。
- 合并和视频分轨文件名包含主标题、BV、列表序号、实际清晰度、编码、音频码率和容器扩展名，例如：

  `标题_BVxxxx_C02_P02_1080P_AVC_AAC_video_audio.mp4`

- 仅下载音频时文件名使用自动识别的 `音乐名_作者.m4a`；无法识别音乐名时回退视频标题。BVID、分 P、CID、编码、码率、来源标题等技术信息写入音频元数据；原始音频回退下载按真实容器使用 `.flac`、`.opus`、`.mp3` 等扩展名。

### 进度与估算

- 每个任务可显示估算文件大小、下载进度、合并进度和综合进度。
- 全局摘要显示总下载速度、按媒体大小加权的综合进度、预计下载时间和预计总计时间。
- 不单独显示全局预计转码时间；合并耗时样本只用于预计总计时间模型。
- 默认约每 500 毫秒刷新，可在设置中调整为 250–2000 毫秒；合并耗时模型保留最近 3 条达到阈值的样本。

## 收藏夹修复

在公开收藏夹页面中，脚本只处理仍显示“已失效视频”的目标卡片：

- 优先使用 B 站官方收藏夹公开元数据，再按 AV 号补充可确认的标题、封面、简介、UP 主、分区、时间、统计和分 P 信息。
- 标题和封面独立恢复；失败时进入明确终态，不永久保留“正在加载数据”。完全失败时使用 `查不到标题（AV号）【鼠标悬停查看简介】` 作为页面显示兜底。
- 仍使用失效占位封面的目标卡片支持悬停或键盘聚焦资料面板，面板固定在视口内并内部滚动，不改变卡片尺寸，也不拦截 B 站原生跳转。
- 正常收藏卡片不会被改写、插入工具菜单或增加资料面板；隐藏条目只有在官方公开接口明确确认时才按原顺序补回。
- 本地缓存只保存公开元数据和有限时间的命中状态，不保存 Cookie、签名 URL、媒体地址或第三方脚本内容。
- 公开收藏夹页提供 `window.__BILIKIT_FAVORITES_FIX_API__.getEntries()` 标准目录接口，返回 BVID/AID、标题、分 P/CID、时长、UP 主和 `source: "public"`；页面右下角的“打开收藏下载”入口会把该目录交给现有下载工作台。
- 收藏下载只处理公开收藏夹，保留收藏顺序，支持单 P、多 P 和多 BV 选择；每个任务按自己的 BVID/CID 重新读取官方 `view` / `playurl`，失败项可在任务列表中重试。可在“收藏夹修复”设置中关闭该入口。

## 设置与限制

首页加载设置位于设置面板中，可分别关闭广告删除、封面预加载和原生自动加载，或调整预加载/自动加载的目标行数；卡片列数、行数和展示位由 B 站原生逻辑决定。

脚本不绕过登录、会员、付费、DRM、地区限制或其他访问控制；未登录提示拦截只隐藏页面提示，不伪造登录态，也不提供免登录评论或 1080p。官方接口或媒体资源不可访问时，会保留失败提示，不伪造数据。下载功能只针对当前页面识别出的同 BV 分 P、合集条目或番剧正片，不处理推荐列表中与当前视频无关的项目。
